# Codex Account Manager

一个在本机运行的 Codex 账号与对话管理工具。通过网页切换账号、编辑配置、维护登录凭据、管理备份，并在电脑之间迁移对话和生成文件。

**Windows / macOS / Linux · Python 3.11+ · 无第三方 Python 依赖 · 无需 Node.js**

本项目为独立工具，与 OpenAI 无隶属关系。网页只监听本机 `127.0.0.1`；每台电脑各自运行，管理自己的 Codex 数据。

## 1. 下载与一键部署

### 准备

1. 安装并至少启动一次 Codex，让它初始化当前用户的数据目录。
2. 安装 **Python 3.11 或更新版本**。Windows 安装时勾选 **Add Python to PATH**；已安装 Codex 附带运行时的电脑也可能直接被识别。
3. 在本仓库点击 **Code → Download ZIP**，解压到任意可读取的目录，保留全部文件。不要在压缩包内直接运行。

也可以使用 Git：

```sh
git clone https://github.com/hanbing427/codex-account-manager.git
cd codex-account-manager
```

### Windows

双击 **`Deploy.cmd`**。脚本会创建桌面 **Codex Account Manager** 快捷方式，在后台启动服务并打开网页。之后直接点击桌面快捷方式即可，不必保留终端窗口。

### macOS

在解压后的目录打开终端：

```sh
sh Deploy.command
```

桌面会生成 **Codex Account Manager.app**。之后双击该入口启动。也可以先 `chmod +x Deploy.command` 后双击部署脚本；系统询问来源时请按正常“右键 → 打开”流程处理。

### Linux

在解压后的目录执行：

```sh
sh deploy.sh
```

脚本会创建桌面和应用菜单启动项；部分桌面环境需要允许 `.desktop` 文件启动。只有 Codex CLI 时，需安装受支持的终端模拟器才能自动打开新会话。

### 一键部署会做什么？

使用已有 Python，创建当前用户的快捷方式，启动本地后台服务，打开实际网页地址。**不需要管理员权限，不自动安装 Python/Codex，不设置开机自启。** 默认端口为 8765，冲突时自动顺延。

电脑缺少环境时，根据提示安装 Python/Codex，再运行部署入口。macOS/Linux 的路径和进程分支有自动测试，但桌面集成仍需在目标系统验证。

## 2. 第一次使用

### 直接登录 ChatGPT

账号配置页面点击 **ChatGPT 登录**，填写账号名称并点击 **前往官方登录**。系统浏览器会打开 OpenAI 官方授权页，在该页面输入邮箱、密码和所需验证码（也支持官方提供的其他登录方式）。授权成功后回到管理器点击 **保存账号**，即可在列表中切换，无需手动导入 auth.json。

需要安装官方 Codex CLI 并加入 PATH；安装后重启管理器服务。登录使用独立临时目录，不覆盖当前正在使用的 auth/config，不会重启 Codex。取消或保存后清理临时文件。重新登录相同账号会更新匹配配置的凭据。密码不会经过或保存在管理器里。若浏览器没有打开，检查系统默认浏览器设置后重试；网络失败或本机 1455 回调端口被占用也会导致失败。

官方登录方式参考：[Codex Authentication](https://learn.chatgpt.com/docs/auth)。

1. 打开网页“账号配置”，查看“当前生效配置”。工具会自动识别已有账号；未知配置会临时保留，并提示命名保存。
2. 点击“保存当前配置”给现有账号命名，或点击“添加账号”，上传 `auth.json` 和可选的 `config.toml`。
3. 第三方 API 服务需提供包含服务地址和 provider 定义的 config；官方 ChatGPT 账号可以只提供 auth。
4. 点击“切换到此账号”，检查目标 provider 和会话迁移范围，再确认“切换并重启 Codex”。

切换会先关闭 Codex、备份当前文件、移除当前生效的 auth/config，再写入目标账号文件并同步旧会话的 provider。最后重新启动 Codex。**正在进行的任务会中断；独立 CLI/IDE 会话请先退出。**

仅 auth 的账号每次切换都会重新生成官方 provider 的最小配置，不继承上个账号的第三方地址。目前生成配置的默认模型为 `gpt-6-astra`；如果账号或服务不支持，请在配置编辑器选择实际支持的模型。有效 auth 可以恢复登录，过期或撤销的登录凭据仍需重新登录。

## 3. 功能说明

| 模块 | 功能 |
| --- | --- |
| 账号配置 | 自动识别当前账号、避免重复保存、添加/删除/重命名账号、仅 auth 账号支持 |
| 配置编辑 | 点击齿轮或账号名称查看源文件路径、打开目录、编辑 auth/config |
| 更新配置 | “保存副本”只更新已存配置；“更新并重启 Codex”保存并应用配置，会提示重启 |
| 图标颜色 | 点击账号图标单独调整颜色，不改凭据、不重启；新账号自动分配默认颜色 |
| 账号导出 | 全部账号一键导出或单账号导出，支持选择保存位置 |
| 备份记录 | 查看切换备份、恢复、逐个删除或批量删除；切换成功后不会自动清空备份 |
| 凭据维护 | ChatGPT OAuth 账号定时检查/刷新；默认一天，可调整间隔、暂停或手动执行 |
| 对话迁移 | 导出全部/所选对话，或整个项目；预览文件、补充文件、导入到另一台电脑 |
| 后台服务 | 重复点击快捷方式复用服务，关闭浏览器后仍运行；网页提供关闭服务按钮 |

### 配置编辑与更新

- **铅笔**：重命名账号。
- **齿轮/账号名称**：查看路径、编辑 auth/config。认证编辑器显示敏感信息，请避免分享截图。
- **账号图标**：单独设置颜色。
- **保存副本**：修改管理器保存的配置，不影响正在运行的 Codex。
- **更新并重启 Codex**：保存编辑内容并应用该账号。请先保存正在进行的工作。

### 凭据维护

默认间隔 **1440 分钟（一天）**，可设为 5–10080 分钟。只维护已保存的 ChatGPT OAuth 账号，API Key 账号跳过。短消息探测会消耗少量账号额度，可在维护设置调整；OAuth 刷新不能保证被撤销的凭据继续有效。后台服务退出或电脑关机时不再执行维护。

## 4. 换电脑：账号和对话怎么迁移

### 账号配置

1. 在源电脑导出全部账号，或点击单个账号的下载图标。
2. 选择 ZIP 保存位置，将文件传到目标电脑。
3. 在目标电脑部署本工具，解压账号 ZIP，通过“添加账号”选择其中的 auth 和可选 config，并填写名称。

账号包含明文登录凭据，请自行妥善保管。账号导出与对话导出是两个独立功能。

### 对话、上下文和生成文件

打开 **对话迁移**，选择范围：

| 导出方式 | 包含内容 |
| --- | --- |
| 导出所选对话 | 所选对话、已存上下文、分页聊天历史、识别到的文档/图片等关联文件及组织信息 |
| 完整备份全部对话 | 全部对话及上述关联内容，另含状态库快照和会话索引；不会复制每个完整项目目录 |
| 导出整个项目 | 指定项目的对话，以及整个项目目录，包括未被对话引用的文件 |

导出前查看文件清单、大小、缺失和排除项；未识别的文件可填写完整路径补充。选择保存位置后生成 ZIP。

在目标电脑：

1. 安装相同或更新版本的 Codex，至少启动一次初始化数据库。
2. 打开“对话迁移 → 导入对话”，选择 ZIP，勾选需要导入的对话。
3. 填写一个本机已存在的文件存放目录。
4. 确认“导入所选并重启 Codex”。文件放到独立 `Codex-Import-…` 子目录，并自动转换对话和项目中的文件路径。

新版包可保留标题、时间、项目关联、分组、置顶和归档等。已有相同 ID 的对话会跳过；不同内容的目标文件不会被覆盖。导入不更换目标电脑的账号，继续对话时使用目标电脑当前 provider。

**恢复范围**：只能恢复本地已有且打包成功的内容。远程链接、已删除文件、未识别的动态依赖、正在运行的软件和外部登录状态无法完整迁移；旧版包缺少的文档需要在源电脑用新版重新导出。版本不兼容时程序会停止导入并保留备份。建议停止生成后导出，避免文件在打包中变化。

## 5. 启动、停止与更新

| 操作 | Windows | macOS / Linux |
| --- | --- | --- |
| 日常启动 | 桌面快捷方式或 `scripts/Start-Web.vbs` | 桌面入口或 `sh scripts/start-web.sh` |
| 显示启动信息 | `scripts/Start-Web.cmd` | `sh scripts/start-web.sh --no-browser` |
| 停止后台服务 | 网页“关闭服务”或 `scripts/Stop-Web.cmd` | 网页“关闭服务”或 `sh scripts/start-web.sh --stop` |

关闭浏览器不会停止后台服务；切换或维护正在写入时，请等完成后再停止。

**更新程序**：先停止服务，再用新版源码替换程序文件（Git 安装可运行 `git pull --ff-only`），重新启动。账号数据不在程序目录中，因此更新程序不会清空账号。移动程序目录后重新运行部署脚本，以更新快捷方式。

## 6. 数据位置与常见问题

默认数据根目录为当前用户的 `~/.codex`；可通过 `CODEX_HOME` 环境变量覆盖，或使用 `python app/launcher.py --home "实际路径"` 指定。

| 相对于数据根目录的路径 | 内容 |
| --- | --- |
| `account-manager/profiles/` | 保存的账号副本 |
| `account-manager/backups/` | 切换前的 auth/config 备份 |
| `provider-migration-backups/` | 会话 provider 迁移备份 |
| `account-manager/profile-revisions/` | 编辑前的配置版本 |
| `account-manager/conversation-import-backups/` | 对话导入前的数据库和界面状态备份 |
| `account-manager/server.log` | 服务日志 |

备份不会在切换后自动删除；“备份记录”支持手动批量清理切换备份及其关联迁移备份。编辑版本和对话导入备份独立保留。

- **网页无法访问**：点击快捷方式重新启动，并使用启动器给出的实际地址；端口可能不是 8765。查看 `server.log`。
- **要求重新登录**：检查 auth 是否属于目标账号、凭据是否撤销/过期、是否被别的电脑同时刷新，及是否存在系统凭据库或启动参数覆盖。
- **找不到 Codex**：先安装/启动 Codex。Linux 使用自定义桌面构建时，可设置 `CODEX_DESKTOP_EXECUTABLE` 为可执行文件的绝对路径。
- **需要局域网访问吗？** 不需要。它管理本机文件，应在每台电脑各自部署，不是公开网站或云服务。
- **导出文件放在哪里？** 浏览器支持时显示另存为窗口，否则输入本机已存在目录的完整路径。
- **导入中断怎么办？** 保留备份，使用页面的“恢复中断的导入并重启 Codex”；状态不一致时停止自动恢复，避免覆盖现有数据。

请勿将 `.codex`、账号包、备份、迁移计划或运行状态文件提交到公开仓库。本仓库只分发程序，不附带个人配置或对话。项目目录导出可能包含 `.env` 等文件，分享前请检查。

## 7. 目录结构

```text
codex-account-manager/
├── README.md          # 快速开始、功能和使用教程
├── Deploy.cmd         # Windows 一键部署
├── Deploy.command     # macOS 一键部署
├── deploy.sh          # Linux 一键部署
├── app/               # Python 程序；ui/ 存放网页和图标
├── scripts/           # 启动、停止、快捷方式与原迁移 CLI 入口
└── docs/              # 详细部署和维护文档
```

日常使用桌面快捷方式即可。请整体移动或更新文件夹，不要单独复制入口脚本。`local/` 如存在，仅用于保留本机旧迁移计划等资料，不上传 GitHub、不随压缩包分发。账号和备份仍保存在各用户的 Codex 数据目录。
